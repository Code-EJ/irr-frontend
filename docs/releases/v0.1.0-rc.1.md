# IRR frontend v0.1.0-rc.1

Maintainer: [Enzo Ribas (@oEnzoRibas)](https://github.com/oEnzoRibas).

This is the frontend **homologation release candidate**, paired with IRR backend v0.1.0-rc.1. The GitHub Release is prepared as a draft/prerelease for owner review. Review [frontend PR #67](https://github.com/Code-EJ/irr-frontend/pull/67) with [backend PR #79](https://github.com/Code-EJ/irr-backend/pull/79).

## Included

- Incremental integration with the final `/api/v1` contract, preserving the existing React/Vite stack.
- Identity, organizations/memberships, catalog/fleet/parties, intake/documents, routes/executions, processing, inventory, buyers/sales and native operational/Analytics pages.
- Brazilian Portuguese interface, grouped navigation, adaptive duration display and theme/font/contrast controls.
- Shared credits for Instituto Referência em Resíduos and Code Soluções em Tecnologia Jr.
- Pinned generated API types, integration checks, dependency/release evidence and manual Railway/portable VPS deployment instructions.

## Install and publish

Follow [manual deployment](../manual-deployment.md). Build the frontend with the destination's public `VITE_API_BASE_URL=https://BACKEND-DOMAIN/api/v1`; never include backend credentials. Source archives are portable, but a bundle built for localhost is not a public hosted bundle. Origin changes require rebuilding.

After owner approval, merge both coordinated PRs and verify main's workflows. Confirm the draft release target/tag and exact matched source references before publication. Publish this candidate as a prerelease; keep stable production releases separate. GitHub publication does not automatically redeploy the manually uploaded Railway services.
